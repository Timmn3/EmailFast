# EmailFast

Коммерческий сервис приёма кодов подтверждения и аренды временных почтовых ящиков.
Биллинг, интеграции с внешними провайдерами, партнёрская программа и фоновая обработка.
В поддержке 22 месяца, 741 коммит.

## Бизнес-задача

Сервис работает с деньгами пользователей и зависит от внешних поставщиков, которые
отказывают, отвечают медленно и меняют поведение без предупреждения. Из этого следуют
два жёстких требования.

Первое: деньги не должны теряться и не должны зачисляться дважды. Платёж может прийти
повторным вебхуком, пользователь может нажать кнопку два раза, внешний сервис статусов
может ответить с задержкой уже после того, как операция закрыта.

Второе: отказ одного поставщика не должен останавливать сервис. Если проверка платежей
недоступна, работа не прекращается - она деградирует контролируемо и восстанавливается сама.

Большая часть инженерных решений здесь выросла из этих двух требований.

## Инженерные решения

**Идемпотентное зачисление.** Повторная доставка события о платеже не создаёт второго
начисления. Зачисление выполняется в транзакции, состояние операции фиксируется до того,
как баланс изменён.

**Ограничение времени всего прохода.** Фоновая проверка платежей ограничена по времени
целиком, а не по отдельному запросу. Иначе задача, запущенная планировщиком в единственном
экземпляре, зависает молча и не запускается больше никогда - до перезапуска процесса.

**Размыкание цепи.** При серии отказов внешнего API проверка приостанавливается и
возобновляется позже, вместо того чтобы продолжать бить в недоступный сервис.

**Автоматическое переключение серверов.** Сторожевой процесс отслеживает доступность
основного узла и переводит работу на резервный.

**Сверка расхождений.** Отдельный механизм сравнивает остаток на балансе с суммой операций
одним запросом - расхождение обнаруживается само, а не по жалобе пользователя.

**Флаги в конфигурации.** Рискованные механики включаются и выключаются без релиза.
На боевом сервисе это разница между «выключили за минуту» и «выкатываем хотфикс под нагрузкой».

**Оптимизация обхода ящиков.** Линейный перебор тысяч адресов заменён выборкой
по активности владельца: время прохода сократилось с 28 минут до 2.

## Возможности

- Приём **SMS** и аренда номеров (интеграции со сторонними провайдерами).
- Аренда **временных e‑mail** (создание, продление, авто‑уведомления об окончании).
- Пополнение баланса через несколько платёжных систем + **Telegram Stars**.
- **Партнёрская программа** с учётом приглашений и вознаграждений.
- Автоматические фоновые проверки и уведомления (**APScheduler**).
- Админ‑статистика: пользователи, SMS/e‑mail, аренды, пополнения и пр.
- Современный стек: **Aiogram 3**, **aiogram_dialog**, **Tortoise ORM + asyncpg**, **Loguru**.

## Технологии

- **Python 3.12**, **Aiogram 3**, **aiogram_dialog**
- **APScheduler** - фоновые задания
- **Tortoise ORM** + **PostgreSQL (asyncpg)**, **Aerich** - миграции
- **Loguru** - структурированное логирование
- Внешние сервисы: SMS‑провайдеры, платёжные системы

## Структура

```
app/
  db/
    models.py          # модели Tortoise ORM
    database.py        # подключение к БД
  dialogs/             # диалоги aiogram_dialog
  services/            # интеграции (платежи, SMS/e-mail и т.д.)
  scheduler_instance.py# экземпляр APScheduler
  dependencies.py      # конфиг и DI (бот, dp, DB_CONFIG)
  config.yaml          # основной конфиг (не коммитить секреты!)
aerich.ini             # конфиг для Aerich (db_url подставляется динамически)
requirements.txt
main.py                # точка входа в приложение
```

## Быстрый старт

```bash
git clone https://github.com/Timmn3/EmailFast.git
cd EmailFast
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # заполнить своими значениями
aerich upgrade                 # миграции
python3 main.py
```

Требуются PostgreSQL и Redis. Подробная настройка - [docs/configuration.md](docs/configuration.md),
планировщик, платёжные провайдеры и логирование - [docs/operations.md](docs/operations.md).
